# 公開前点検

実施日：2026-10-19。結論：公開設定を準備し、ユーザーの承認後にGit履歴のメールとリポジトリのGit設定を修正した。通常履歴の点検は成功。古いコミットへの参照は残るため、[対応記録](email-privacy.md)を参照する。Pagesは未デプロイ。

## 1. ユーザーによる確認

スマホ実機での確認は、ユーザーから「1はOK」との報告を受け完了として記録する。これは先に案内した画像読み込み・解析・色の選択・結果保存の確認についての報告。機種名、OS、ブラウザと各バージョンは未記録であり、全スマホ・Safariの網羅的な検証済みとはしない。端末固有情報は収集しない。

## 2. 点検結果

| 対象 | 結果 |
|---|---|
| ソース・文書・公開候補 | パターン検査で秘密・非公開用ではないメール・個人ローカルパスを検出しなかった。禁止形式とシンボリックリンクも検査 |
| ローカルデータ | .local、ログ、dist、node_modules等はGit除外。ユーザー画像は追跡候補に含まれない |
| 公開ビルド | アプリと必要な通知・資産の7ファイル。比較ページ、画像、ログ、文書、ソースマップ等は配信しない |
| 依存 | 固定済みnpm依存への `npm audit` は全重大度0件。照会時点の既知情報で、脆弱性不在の保証ではない |
| ライセンス | MIT本文とViteの配信ヘルパーの通知を維持。第三者の権利表示を個人情報検査のために削除しない |
| アプリの通信・保持 | 許可済み同一オリジン資産の取得のみ。画像・名前・結果の送信やCookie・永続ストレージへの保存はテストで検出されなかった |
| 初回コミット | 著者・コミッターのメールを非公開用へ置換し、GitHubのmainに反映済み。元のメールと旧コミットの識別子は再掲しない |
| 今後のGit著者設定 | このリポジトリのメールを非公開用に変更済み。他のリポジトリとGitHubアカウント全体の設定は変更していない |
| 公開設定 | 検証と公開権限を分離し、履歴点検と明示的な有効化を公開条件にした。GitHub側への適用は未実施 |

ユーザーがコミット履歴の変更を承認したため、初回コミットの内容と日時を維持してメールを置換した。変更前のmainと一致する場合だけ更新するforce-with-leaseでGitHubにも反映した。既に公開された情報の完全な回収を保証するものではない。

## 3. 実装した確認手段

- `npm run audit:source`：Git追跡中とGit除外されていない未追跡ファイルを検査。
- `npm run audit:history`：公開対象となるローカルブランチ・タグとリモート追跡refのコミット識別情報・メッセージ・ファイルを検査。ローカル編集ツールの内部チェックポイントやreflogは公開対象に含めない。shallow cloneは未点検範囲があるため失敗にする。
- `npm run audit:dist`：公開用ビルドの許可ファイル、資産一覧との一致、CSPとReferrer方針、ソースマップ等を検査。

検出時の出力は規則名と場所だけで、マッチした秘密やメールの値を出力しない。公開履歴の名前は指定ハンドルとGitHub・botの識別名を許可し、それ以外は要確認とする。今後のコントリビューターにも公開用の識別情報を使用してもらう。

これらは既知形式の検査であり、自由文中の本名・住所・画像に写った情報などを完全に自動判定するものではない。Git除外は追跡済みの秘密を消さない。点検はGitに認識された履歴を対象にし、既に他者へ渡った複製は対象外。実ファイルと差分の目視確認も併用する。

## 4. 検証と残件

ロックファイルからの `npm ci`、単体テスト17件、比較画面6群、公開用ビルドでの本体14群のブラウザ検証が成功した。ソースと配信7ファイルの点検は指摘0件。当初は履歴のメール2箇所を検出して失敗したが、承認後の修正により公開対象履歴の再点検も成功した。古い参照の残存は、この検査の成功とは区別する。意図的に不要なログを配信物へ混入する試験では、許可外ファイルと資産一覧の不一致を検出し、試験後に取り除いた。

YAMLの構文、固定SHA、権限、PRの公開禁止、有効化条件もローカルで確認済み。Windows上の検証であり、GitHub ActionsのUbuntu runner上での初回実行は未実施。

残件は、古いコミットへの参照の扱い、GitHub側のPages設定反映、非公開脆弱性報告の有効化、Actionsでの成功確認、実際の公開URLの疎通確認。[公開手順](publishing.md)に従う。入力上限の端末別メモリ評価やアクセシビリティ全体の適合監査についても、従来の未確認事項を完了扱いにしない。
