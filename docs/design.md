# 画面・デザイン仕様

状態：2026-10-19、ユーザーが暫定採用したA（ギャラリー型）を全機能画面に統合済み。公開は未実施。比較ページは参考として残す。[比較と判断理由](design-comparison.md)

## 1. 方向性と理由

画像と色の構成を主役にし、無彩色の背景、余白、細い罫線、整列した数値で見せる。装飾より、画像・色帯・割合の関係が読み取りやすいことを優先する。Aを推奨した理由は、繰り返し使う解析ツールに向くため。ユーザーはAを暫定採用したが、その個人的な選択理由は推測しない。

外部フォント、外部画像、アイコンライブラリは読み込まない。OS標準のサンセリフを使用する。画像周辺は無彩色で、透明部分は市松模様を使う。解析色に応じて画面全体を着色しない。ライトテーマのみで、テーマや設定の永続保存は行わない。

## 2. 画面構成

- ヘッダー：アプリ名、試作版表示、画像の取り扱いへのリンク。
- 導入：短い説明と端末内処理の案内。
- 画像選択：ファイル選択、ドロップ、自作サンプル、対応形式・上限。
- 作業領域の左：画像名・寸法、クリア、原寸データを保持したプレビュー、画素検査、色帯と凡例。
- 作業領域の右：集計対象のうち最も多い色と割合、系統別ボタン、解析条件・再解析。
- 下部：全画素・対象・除外・色数の統計、一覧・検索・並び替え、CSV/JSON保存、精度とプライバシー説明。

最初は画像選択と使い方を表示し、画像の読み込み後にプレビューと設定を表示する。画像を選んだだけでは解析しない。「解析する」で結果を表示する。最も多い色は、その解析方法の件数順の先頭から取得する。完全一致ではカラーコード、色系統別では系統名、固定区間分類では代表コードを表示する。

表示の全体確認と厳密な検査を両立するため、拡大・座標検査、透明度などの詳細設定、色の一覧は折りたたむ。画像をタップするか、画像にフォーカスして矢印キーで選択すると、画素検査を開く。通常の画面では視覚的な負担を抑え、必要なときに詳細へ進めるため。

解析条件は画像読み込み時には開く。解析完了時は閉じて結果を優先する。「解析条件・再解析」で再び開く。解析ボタンにフォーカスして完了した場合は、その折りたたみの見出しへフォーカスを移す。キャンセル・進捗は設定の折りたたみの外に置き、設定を閉じても到達できるようにする。

系統ボタンは件数が多い順に並べる。0件の系統は「使われていない系統」にまとめ、開いて確認できるが選択できない。存在する系統はすべて表示し、「その他」で省略しない。分類ルールと分母は変更しない。

最も多い色と系統ボタンの割合は小数点以下2桁に丸め、0より大きく0.01%未満なら「<0.01%」と表示する。一覧と色帯の凡例では従来の詳細表示を維持し、出力データは丸めない。集計対象が0なら主要色は「集計対象なし」、割合は「—」とする。

## 3. 見た目の基準

| 用途 | 実装値・方針 |
|---|---|
| ページ背景 | #FAFBF9 |
| 解析パネル | #FFFFFF、細い境界線、影なし |
| 主文字・補助文字 | #272F2B・#59685E |
| 操作のアクセント | #345E63 |
| 境界線 | #DCE1DA |
| 画像周辺 | 無彩色の市松模様 |
| 主要な割合 | 大きな等幅数字、系統名とセットで表示 |
| 形状・余白 | 角丸2pxを基本とし、罫線と余白で区切る |
| 書体 | OS標準サンセリフ。カラーコードは等幅 |

文字やラベルを色と併記し、色だけで意味を伝えない。系統の選択はaria-pressedと枠でも示す。色見本は境界線を持ち、白・透明も区別する。画面の色は測色機器の代わりにはならない。

## 4. レスポンシブと操作

幅900px未満では画像・色帯→主要色と系統→解析設定→詳細結果の縦配置にする。幅320pxでもページ全体が横にはみ出さず、表だけは専用領域内で横スクロールできる。画像は全体表示を初期値にして縦横比を保つ。倍率や画面幅の変更によって解析する画素数を変えない。

プレビュー枠は固定の横長にせず、読み込んだ画像の縦横比に合わせる。利用可能な列幅と画面の高さから全体表示のサイズを求め、周囲に20pxずつの余白を付けて中央に配置する。高さの上限は画面高の72%を目安に240〜720pxの範囲で設定する。画面高には、アドレスバー等を表示した状態の高さ（CSSの`100svh`、非対応環境は`100vh`）を使う。スマホのスクロールでアドレスバーが伸び縮みしても、枠と画像の大きさを変えないため（2026-10-20、ユーザーの画面録画で縦長画像の大きさが変わる不具合を確認し修正）。極小画像は原寸を超えて自動拡大せず、操作のため枠だけ最低160pxを確保する。縦写真の左右に大きな市松模様を残さず、写真自体も固定高のときより大きく確認できるようにするため。

手動ズームでも枠は元画像の縦横比から求めた大きさを保ち、拡大部分は枠内でスクロールする。画面幅・高さの変更時には再計算する。切り抜きや解析用画像の縮小は行わない。

ボタン・入力・折りたたみ見出しは44px以上の操作領域を基本とする。ファイル選択、座標入力、矢印による画像移動を用意し、ドラッグやホバーだけに依存しない。本文へのスキップリンク、フォーカス表示、フォームラベル、HTML表、進捗と状態の読み上げを備える。OSの動きを減らす設定を尊重する。

WCAG 2.2 AAを目標とするが、全面的な適合監査は未完了。Chromiumの自動検証とスマホ幅・タッチエミュレーションの成功を、スマートフォン実機・Safariでの検証済みという意味にはしない。
