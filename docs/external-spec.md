# 外部仕様

R-01〜R-20を除く詳細は提案。D-04の入力上限は暫定採用済みで、実測後に最終化する。未確定の対応範囲は検証・確認後に確定する。0.2.0で追加した色系統別モード・強調表示・出力v2の詳細は[色系統別集計](color-families.md)を参照し、初期モードと出力の旧記載より優先する。

## 1. 利用の流れ・画面状態

A（ギャラリー型）を全機能画面に統合済み。配置、主要色の表示、詳細パネル、0件系統の折りたたみ、割合の表示精度は[画面仕様](design.md)を参照する。計算・出力の精度と分類ルールは変更しない。

初期画面 → ファイル検証 → 読み込み → 解析可能 → 解析中 → 結果表示。

初期画面に画像選択、対応形式、上限、端末内処理の説明を表示する。ファイルを選んだだけでは解析を開始せず、初期条件を確認して「解析する」を押す。画像プレビューは読み込み完了後から使える。

解析中は進捗とキャンセルを表示する。設定変更時は旧結果を無効化し「条件が変わりました。再解析してください」と表示。完了するまでは出力不可。画像の差し替えは旧処理を中断・旧データを解放してから行う。不正な差し替えの場合も旧結果は復活させない。

レビュー補足：初期モードは0.2.0から「色の傾向」。新しい画像は既定の解析条件で開始し、プレビュー倍率・選択座標・系統の強調・検索・ページ位置もリセットする。ファイル選択ダイアログをキャンセルしただけなら現在の画像を維持する。同じファイルも選び直せるようにする。検証・読み込み・解析・出力準備中は解析設定を変更不可にし、キャンセルとクリアは利用可能にする。画像差し替えも処理を中断してから受け付ける。通常時に解析条件を変更した場合のみ再解析待ちとする。

キャンセル後は画像と設定を保持して解析可能へ戻り、中間結果は表示しない。クリアは解析の有無にかかわらず画像・結果・設定・ファイル入力を初期化する。再読み込み時は復元しない。履歴からの復帰（BFCache）でも初期化する方針。

エラー時の扱い：入力検証・復号の失敗は初期画面へ戻す。読み込み完了後の解析失敗は画像と設定を残し、失敗した結果だけ破棄する。出力準備の失敗・キャンセルは完成済み解析結果を残す。いずれもクリアで全状態を解放できる。検証・復号中のキャンセルは初期画面へ戻し、後から完了した処理の画像を表示しない。

## 2. 入力

| 項目 | 仕様・提案（確定範囲はR項目を参照） |
|---|---|
| 選択方法 | ファイル選択またはドラッグ＆ドロップ。タッチ端末は選択ボタン |
| 枚数 | 1枚。複数同時選択はエラー |
| 形式 | 静止PNG/JPEG/WebP。拡張子のみを信用しない |
| 上限 | 暫定採用：20MiB（20×1024×1024バイト）、1600万画素、一辺8192px。いずれか超過で拒否。自動縮小せず、実測により上限を調整する |
| 色数上限 | 完全一致で異なる色が100万を超えたら中断。部分結果を完成扱いにしない |
| 縦横 | EXIF向き情報を反映した表示方向を採用。寸法と座標もこの向きに統一 |
| 色 | ブラウザ復号後にsRGB・8bit RGBAとして取得 |
| 画像名 | 画面内のみ表示可能。外部送信、出力、ログへの記録なし |
| メタデータ | GPS・撮影日時などを抽出・表示・保存しない。向き情報のみ必要な内部処理に利用 |

画像の小さなファイルサイズは安全性を保証しない。寸法を事前確認し、巨大画像を復号前に拒否する。破損、未対応形式、アニメーション、復号失敗は原因に応じて案内する。形式判別・アニメ判別を実装できない形式は対応済みと表示しない。

## 3. 完全一致モード

解析元寸法の全画素を走査する。RGB各成分とalphaは0〜255の整数。HEXは大文字でRGBなら`#RRGGBB`、RGBAなら`#RRGGBBAA`とし、alphaの整数値も別列で示す。

| 設定 | 選択肢・既定値 |
|---|---|
| 一致条件 | 確定：RGBA一致（既定）／RGB一致（alphaをキーに含めない） |
| 透明度の対象 | 完全透明を除外（既定）／全画素は確定。不透明のみの選択肢は将来候補とし、初期版の推奨実装から外す |

完全透明はA=0、半透明は1≦A≦254、不透明はA=255。半透明も対象なら1画素として数え、透明度による重み付けはしない。RGB一致は同じRGBのalpha違いをまとめるが、背景への合成はしない。完全透明画素のRGBは元ファイル値を維持できないことがあるため、全画素を含める場合は説明を表示する。

分母Nは透明度条件を適用した対象画素数。各色の割合は`count / N × 100`。除外画素は分母に入れない。全画素数・対象数・除外数・透明度別件数・異なる色数を表示する。対象0なら空結果とし、割合を計算しない。

例：4画素が赤255・赤128・青255・透明0の場合、既定条件ではN=3。RGBA一致は3色が各1/3、RGB一致は赤2/3と青1/3。透明度別件数は全画素を対象として不透明2、半透明1、透明1。

## 4. 類似色モード

完全一致とは別モードとして明示する。「RGBを一定の区間でまとめた概算分類」であり、知覚的に近い色を保証しない。全対象画素を使い、画素のサンプリングはしない。

一定の区間でRGBを分類する基本方式はD-06で確定。以下の詳細は実装設計の提案：各RGB成分を幅16または32（既定32）の区間に分割。同一区間のRGBを同一グループとして数える。代表RGBは所属画素の成分別平均を四捨五入する。alphaはキーに含めず、対象の選択条件だけに用いる。グループID・代表RGB・件数・割合を表示し、代表色そのものの出現件数と誤認させない。区間境界をまたぐ近い色は別グループになる。

## 5. 結果と単一画素検査

色テーブルは件数降順、同数は数値キー昇順。完全一致・固定幅分類では初期表示50件、ページサイズ50/100/200件の切替を設計候補とする（試作は50固定）。全件は保持し、表示分だけで割合を再計算しない。HEX検索、件数順・色コード順の切替を設ける。色系統別では存在する全系統を表示し、HEX検索を無効にする。名前と平均RGB、件数、割合を併記する。

検索の推奨規則：前後空白を除き大文字化した`#RRGGBB`または`#RRGGBBAA`のみを受け付ける。空欄は検索なし。RGBA一致で6桁なら同じRGBの全alpha、8桁ならRGBAの一致を検索する。RGB一致・類似色では6桁のみとし、類似色では代表RGBを検索する。入力途中や形式不正では案内を出し、0件と区別する。検索・並び替え時は先頭ページへ戻す。検索は表だけに適用し、全体の統計・グラフ・保存内容は変えない。類似色モードの色コード順は代表RGB昇順・同値はグループID昇順。表示は「色数」でなく「グループ数」とする。

完全一致・固定幅分類の帯グラフは上位10件と「その他」を表示する。「その他」は表示外の全件の合計で、その表示色は実画像の色を意味しない。色系統別の帯グラフは存在する全系統を表示し「その他」を作らない。テーブルにも正確な整数件数を併記。割合は小数第4位まで表示し、微小な正の割合は「<0.0001%」と表示。丸めにより表示割合の合計が100%にならない旨を記載する。

プレビューは拡大・縮小・移動・全体表示に対応し、100%では画像1画素をCSS上の1pxとして扱う。端末の物理画素との同一性は保証しない。クリック／タップ／座標入力で画素を選択し、十字マーカーと座標・RGB・alpha・HEXを表示する。キーボードの矢印でも選択位置を動かせる。

座標原点は向き補正後画像の左上(0,0)、xは右、yは下。範囲外は選択不可。縮小表示から選ぶ場合も解析元座標を計算し、拡大描画用の色を読み取らない。色見本は透明市松模様上に表示するが、数値は背景合成前の値。

プレビューの推奨詳細：表示倍率は全体表示および25〜3200%の範囲とし、拡大時は平滑化しない。全体表示が25%未満でも許可する。ドラッグ移動とタップ選択を区別し、拡大・縮小・移動・座標入力をボタンでも行えるようにする。ピンチ操作は補助とし必須にしない。透明度をまとめた行の色見本は不透明な代表RGBとして表示し、画像の実際の見え方とは区別する。対象0なら色表・グラフは空状態とし、統計とJSON保存は利用可能、CSVはヘッダーのみと案内する。

## 6. 出力

明示操作でCSVまたはJSONを端末にダウンロードすること、元画像・元ファイル名・撮影情報を含めないこと、アプリ内履歴を設けずクリア後もダウンロード先に残ることはD-08で確定。既定名は`color-analysis.csv` / `color-analysis.json`とし、サムネイル・出力日時・ブラウザ識別情報も含めない設計案。以下の列・スキーマ・全件出力などの詳細も提案とする。

JSONはschemaVersion、appVersion、幅・高さ、測定基準、モード、対象条件、一致条件または量子化設定、全画素数、対象数、除外数、透明度別件数、全色行を含む。各行はkey、代表色または色成分、count、ratio（0〜1の未表示丸め値）。CSVも同じ情報を各行の固定列に展開し、対象0ならヘッダーのみ。空結果の設定はJSONで確認できる。

表示中ページや検索条件で出力を削らず、解析全件を出す。件数を唯一の厳密値とし、割合の数値は有限精度の計算結果。出力は画像寸法や配色情報を含むため、利用者自身による共有の前に確認する旨を出力欄に記載する。

スマートフォンを含む保存手順の推奨設計：「CSVを準備／JSONを準備」→準備完了後の「ダウンロード」の2段階にする。重い準備を終えてから改めて押すことで、保存動作を利用者の直接操作に結び付ける。準備中は進捗段階とキャンセルを表示する。同時に準備する形式は1つとし、再準備・条件変更・クリアで旧Blobを破棄する。保存の開始は案内できるが、OSの保存ダイアログでの完了・キャンセルや保存先をアプリが確認できるとは表示しない。ダウンロード直後にリンクを失効させず、再保存できるよう次の破棄操作まで有効にする。

## 7. エラー・対応環境

エラー種別：形式不正／非対応／容量超過／寸法超過／破損／復号不可／Canvas未対応／画素読み取り不可／メモリ不足／出力失敗。エラーは復旧操作を添えた日本語で表示し、スタックやファイル内容を表示・送信しない。ブラウザがタブを強制終了した場合はアプリ内案内を保証できない。

PC・スマートフォンの両方を初期版の正式対応対象とする方針はD-09で確定。レスポンシブ表示に加え、画像選択・設定・解析・画素確認・CSV/JSON保存・キャンセル・クリアを双方で利用可能にする。

検証対象の提案：公開時点のデスクトップChrome/Edge/Firefox/Safari安定版と、iOS Safari・Android Chromeを対象に実測し、対応バージョン・確認範囲を記録する。モバイルの写真選択でHEIC等の対象外形式が渡された場合は形式の案内を出す。上限と速度は端末ごとに実測し、全端末で同一性能とは説明しない。JavaScriptとWeb Workerが使えない場合は解析を無効にし理由を表示。国・ネットワークによる接続制限やブラウザ保護機能による画素値変更は保証範囲外とする。
