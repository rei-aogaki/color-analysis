## 読み方と変更管理

最初に要件・決定管理の未決定事項を確認する。数値集計の定義は外部仕様、実現方法は内部仕様を正とする。不整合は実装前に修正する。

初回レビューで追記した詳細は、確定した基本方針を実現するための推奨設計であり、ユーザーが各詳細を個別承認したという意味ではない。レビュー結果の「文書修正済み」と「実機検証済み」は区別する。推奨値や性能目標の最終化は技術試作で行う。

各判断について、決定時と変更時の両方で理由・制約・見直し条件を判断理由の記録へ残し、影響する文書・検証項目を要件の決定記録に追加する。未決定の項目は採用済みとせず提案理由として記載する。設計上の理由と、ユーザーが明示した理由を混同しない。動作に影響する変更では、対応する仕様・型・テストも同時に更新する。

この初版は詳細設計のたたき台であり、公開前の検証結果を示すものではない。公開日・アプリURL・性能実測値は未設定。

0.2.0で色系統別の「色の傾向」を初期モードとして追加した。最新の分類と表示・出力の契約は色系統別集計の文書を参照する。prototype-results.mdの初回性能値は0.1.0当時の測定で、分類追加後の性能と混同しない。

D-01〜D-10の基本方針は確定済み（D-04の上限値は暫定）。D-10はMIT、アプリ名color-analysis、著作権者名rei-aogakiで確定し、LICENSE作成済み。D-05の「不透明のみ」、D-06の区間幅、D-08の出力スキーマ、D-09の性能目標などは未承認の詳細提案として区別する。
