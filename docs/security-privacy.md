# セキュリティ・プライバシー仕様

## 1. 保持しない方針

確定方針：アプリ運営者はユーザー画像・個人情報を収集・永続保存しない。ログイン、独自セッションID、アクセス解析、広告、クラッシュ送信、利用履歴、フィンガープリントを設けない。

「セッションが切れたら消す」だけでなく、利用中も永続ストレージへ書き込まない。サーバー側セッションは存在せず、ここでいうセッションはページ上の一時的な作業状態。Cookie、localStorage、sessionStorage、IndexedDB、Cache Storage、Service Workerをユーザーデータ・設定の保存に利用しない。

アプリのコードやCSSは通常のHTTPキャッシュに残り得る。ブラウザの履歴・OSのスワップ・クラッシュ復元・拡張機能・端末バックアップまで消去する保証はできない。「情報が世界のどこにも残らない」「完全消去」とは表現しない。

## 2. データの流れ（提案）

| データ | 場所・期間 | 送信／出力 |
|---|---|---|
| HTML/CSS/JS | GitHub Pagesから取得、通常のブラウザキャッシュ対象 | 公開資産の配信のみ |
| 選択した画像・名前 | Fileとしてページのメモリ内、クリア／差し替え／検知できたページ離脱で解放 | 外部送信なし、名前は出力にも含めない |
| ピクセル・解析結果 | ページ／Workerメモリ、同上 | 外部送信なし |
| 設定 | ページメモリ、同上 | 保存・URL埋め込みなし |
| EXIF等 | 元Fileに含まれ得る。必要な向き処理以外に利用しない | 抽出保存・出力・送信なし |
| CSV/JSON | 明示ダウンロードした利用者の端末 | 利用者の操作で保存。クリアでは削除しない |
| IP等の接続情報 | ホスティングサービス側 | GitHub側の管理。アプリ運営者による収集とは別 |

初回表示にはページ配信へのネットワーク通信が必要。後からWorkerなどの同梱静的ファイルを同一オリジンから取得する場合もあるが、画像・名前・解析結果・設定などのユーザーデータを送信しない。許可する要求はビルド資産一覧にある固定パスへの取得のみで、ユーザーデータをURL・クエリ・フラグメント・ヘッダー・本文へ埋め込まない。画像解析用API、外部CDN、計測サービスには接続しない。静的取得に伴う配信元側のアクセス記録はD-02の扱いに従う。

一時的なタブ切替・画面回転・OSの写真選択画面への移動は、作業終了とは扱わない。ページメモリには画像・結果を保持し得るが、永続保存は行わない。クリア・画像差し替え・受信した離脱イベントでは解放し、履歴復帰時は初期化する。モバイルでは離脱イベント自体が必ず届くとは限らないため、端末上の一時メモリの即時消去は保証しない。[ブラウザのイベント制約](https://developer.mozilla.org/en-US/docs/Web/API/Window/pagehide_event)

## 3. GitHub Pages側の扱い

GitHubの公式説明では、Pages訪問者のIPアドレスはログイン状態に関係なくセキュリティ目的で記録・保存される。アプリからGitHub側ログの停止や削除を制御できるとは記載しない。[GitHub Pages概要](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

したがって「アプリがユーザー情報を保持しない」は実現方針にできるが、「ホスティング事業者も情報を一切保持しない」はPagesでは満たせない。D-02でGitHub Pages側のIP記録を許容することが確定した。アプリ側の非収集・非保存方針は維持し、説明では両者を区別する。保持期間など未確認事項や、責任の全範囲がGitHubにあるという法的判断を推測して書かない。

画面向けの提案文：

> 画像はこの端末のブラウザ内で解析します。画像・解析結果・設定をアプリから送信したり、永続保存したりしません。配信元のGitHub Pagesでは、セキュリティ目的で訪問者のIPアドレスが記録されます。

## 4. 想定する脅威と対策（提案）

| 脅威 | 対策 | 残る制約 |
|---|---|---|
| 大容量／高圧縮画像によるメモリ枯渇 | 復号前寸法検証、ファイル・画素・色数上限、Worker・キャンセル | 復号時のブラウザ内部使用量や強制終了は完全制御できない |
| 偽の拡張子・壊れたヘッダー | シグネチャ、範囲、寸法検証、ブラウザ復号失敗の捕捉 | ブラウザ本体のデコーダーの脆弱性をアプリだけで排除できない |
| SVG等からのスクリプト・外部参照 | 対応形式の許可リスト、SVG/HTML拒否、URL画像入力なし | 対応形式を増やすときに再評価が必要 |
| ファイル名等によるXSS | textContent等で表示、innerHTML/eval禁止 | 依存コードの混入にも注意する |
| CSV数式注入・情報混入 | 固定列と数値・固定文字列のみ。元ファイル名を除外 | 利用者が出力後に追加した内容は対象外 |
| 古い結果の混入 | jobId検証、変更時無効化、破棄処理 | ページ停止中の即時処理は保証しない |
| 外部スクリプト・依存の侵害 | CDN/外部フォント/解析SDKなし、依存固定、更新レビュー | 静的配信でもビルド依存の検査は必要 |
| 公開ファイルへの秘密情報混入 | 公開物・Git履歴・ビルド成果物を確認 | .gitignoreだけでは追跡済み情報を除去できない |

## 5. ブラウザ側制限・配信方針

自サイト資産のみを同梱し、外部フォント・埋め込み・第三者画像・テレメトリを使わない。結果コピーは明示操作時のみクリップボードへ書き、読み取り権限は要求しない。カメラ・位置情報・通知権限を要求しない。

提案CSP：default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' blob:; worker-src 'self'; connect-src 'none'; font-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'。画像をCanvasでのみ描く場合もプレビュー実装に合わせて最小限にする。インラインコード・インラインイベントを使わず、実際のビルドとWorkerが動くことを検証する。

worker-srcはWorkerの読み込み元を制限するものであり、Worker内の通信すべてをページのmeta CSPで禁止できるとは扱わない。Worker内部にもネットワーク処理を実装せず、ページ・Worker双方の通信を検証する。[WorkerとCSP](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers) 開発サーバーの更新用通信と本番の動作確認は分け、出荷するHTMLでCSPを緩和しない。棒グラフはローカル生成SVGの図形属性やCanvasを使う案とし、可変幅のためにインラインstyle属性を必要とする設計を避ける。

Pagesでは任意のHTTPレスポンスヘッダーを設定する前提にしない。CSPはHTML先頭付近のmetaで適用できる範囲を使い、Referrer-Policyはmetaのno-referrerを提案。frame-ancestorsなどmetaで適用できない制限を適用済みと主張しない。厳格なヘッダー制御が必要なら公開先を再検討する。HTTPSを公開時に確認する。[CSPの仕様と適用方法](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy)

## 6. 公開リポジトリ・運用

実装した公開前チェックと未解決の指摘は[公開前点検](release-review.md)、CI権限・公開有効化・停止の手順は[公開手順](publishing.md)を参照する。初回履歴のメールはユーザーの承認に基づき非公開用へ置換し、公開対象の履歴点検は通過した。古いコミットへの参照は残るため、[対応記録](email-privacy.md)を参照する。値は文書やログに再掲しない。

実ユーザー画像・顔写真・機密画像・個人名・メール・ローカル絶対パス・資格情報を文書、テスト、Issue添付、ログ、成果物へ含めない。例外としてユーザーが公開用著作権者名として明示指定したrei-aogakiの表記は使用する。これを本名やメールなどの追加公開の許可とは扱わない。サンプルはコードで生成した単色・透明度パターンなどを使う。権利が不明な画像を採用しない。

GitHub Actionsの権限はジョブ単位で最小化。未信頼PRでは公開用権限を与えず、ビルド結果を本番公開しない。Actionsは固定コミット参照を候補に、依存ロック・依存更新の確認を行う。公開ソースへ秘密を置かず、クライアント環境変数は秘密にできないものとして扱う。

Gitの著者情報は履歴に残る。公開前に権利者が公開用の識別情報／noreplyメールと過去履歴を確認する。既存履歴の書き換えは本作業では行わない。問い合わせは公開Issueを候補とし、「実画像・個人情報を添付しない」と案内する。非公開の脆弱性報告経路は公開前に決め、個人の連絡先を勝手に掲載しない。
