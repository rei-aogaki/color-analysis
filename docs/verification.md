# 検証・受入基準

本書は本番公開前の受入基準。ローカル試作の初回単体・Chromium検証を実施済みで、確認した項目と未実施項目は[試作結果](prototype-results.md)に記録した。以下の全項目が完了したわけではなく、試作の動作確認と本番受入完了は別に管理する。

## 1. 数値精度

| ID | 検証 | 合格条件 |
|---|---|---|
| T-01 | 既知RGBA配列の完全一致 | RGB/RGBA、透明度2条件（完全透明除外／全画素）の全組合せが手計算と一致 |
| T-02 | 赤255・赤128・青255・透明0の4画素 | 外部仕様のN=3、RGBA3色／RGB2色と一致 |
| T-03 | 0、1、254、255のalpha | 対象・除外・透明度別件数と境界判定が一致 |
| T-04 | 同率・微小割合・全透明・1画素 | 安定ソート、微小値表記、ゼロ除算なし |
| T-05 | 量子化の区間境界 | 15/16、31/32、255等のグループと平均の丸めが一致 |
| T-06 | 全数集計の不変条件 | 色件数合計=対象数、対象+除外=総数、透明度3区分合計=総数 |
| T-07 | 原寸とプレビュー | 倍率・画面幅・DPRを変えても結果不変。間引きなし |
| T-08 | 画素座標 | 四隅、拡大・移動後、向き補正後、座標入力が正しいRGBAを返す |
| T-09 | 色系統別分類 | 原色・無彩色・明暗の異なる青・C/L/hの境界が標準ルールv1と一致 |
| T-10 | 全件分類と表示 | ラベル各キーの個数が統計件数と一致。全13系統が存在する入力でも省略・その他なし |
| T-11 | 分類箇所の強調 | 該当箇所だけ元色、対象外は暗く、完全透明は専用表示。解除・切替・クリアが正しく、画素検査・出力・分母が変わらない |

純粋な集計関数は、Canvasを経由しない既知配列を基準に検証する。復号・Canvasは別テストにして原因を分ける。不透明のsRGB 8bit PNGは生成時に既知の色と件数を定義し、読み取り結果も照合する。

半透明・完全透明の隠れたRGB、ICC付き画像、16bit PNG、JPEG、EXIF回転付きJPEGはブラウザごとに特性を記録する。元の数値と一致しない場合に「誤差ゼロ」と表示しない。ブラウザ間一致を保証していない形式に、一つのデコーダー由来の期待値を無条件で適用しない。

## 2. 入出力・状態

形式偽装、破損、アニメ、複数選択、上限の直前・同値・直後、異なる色数上限、メモリ不足時の扱いを確認する。Workerが応答しなくてもキャンセル・クリアが可能なこと。旧jobの遅延結果が新しい画像に表示されないこと。

CSV/JSONは全件を再読込して元の整数件数と一致すること。CSVのalpha/step/match空欄規約、JSONのschemaVersion、対象0、全ページ分の出力を確認する。画像名・EXIF・ローカルパス・日時・ブラウザ情報が出力へ混入しないこと。

クリア、画像差し替え、再読み込み、検知できたページ離脱・履歴復帰で以前の画像・結果が復元されないこと。解析キャンセルのみでは画像が残り、再解析できること。ダウンロードしたファイルはクリアで消えないことを説明する。

失敗は段階ごとに分ける：入力・復号失敗では画像なし、解析失敗では画像・設定を保持、出力失敗では完成した集計結果を保持する。検証・復号の完了前にクリア／差し替え／キャンセルし、遅れた応答が画像や結果を復活させないことを確認する。タブ切替・写真選択ダイアログのキャンセル・画面回転で入力を失わないこと。OSによるページ破棄や強制終了後のメモリ消去は試験で保証できたものとして扱わない。

EXIF向き1〜8（反転含む）、復号前後の寸法不一致、ヘッダーの長さ偽装、PNG/WebPのアニメ指定・後方フレーム、JPEGのマーカーとEXIF範囲外参照を合成画像で試験する。パーサーの構造要素上限は画像上限とは別のエラーとして確認する。

検索の6桁／8桁、空欄・入力途中・不正値・該当なし、同じRGBで異なるalpha、類似色の代表RGB一致、並び替えとページ移動を確認する。検索しても全体の分母・グラフ・出力件数が変わらないこと。割合は画面表示とCSV/JSONのratioを別々に検証する。

## 3. セキュリティ・プライバシー

現行のソース・履歴・配信物の点検コマンドと結果は[公開前点検](release-review.md)に記録する。スマホ実機についてはユーザーから一連の操作がOKとの報告を受けた。機種・ブラウザのバージョン別の網羅的な確認とは区別する。

合成画像のみでテストする。新しいブラウザコンテキストで初回表示から画像選択・解析・再解析・出力・クリアまで、ページとWorkerのネットワークを記録する。許可するのはビルド資産一覧に一致する固定パスへの同一オリジン取得だけ。画像・名前・設定・結果の送信が0件、外部CDN・計測アクセスが0件であること。Workerの再起動やキャッシュ有無による静的ファイル取得を、画像送信と誤って判定しない。利用者のダウンロードはローカルBlob由来であること。

Cookie・local/sessionStorage・IndexedDB・Cache Storage・Service Workerにアプリがデータを作らないこと。通常の資産HTTPキャッシュは対象外として区別する。明示操作なしのクリップボード書込みや権限要求がないこと。

悪意あるファイル名をテキストとして表示し、コードが実行されないこと。CSPの適用と公開版のWorker起動・Blob画像表示・ダウンロードの両立を確認する。GitHub側のIP記録を説明し、「一切記録されない」という表示がないこと。

公開差分・Git履歴・Actionsログ・distを確認し、秘密や個人情報がないこと。依存とライセンスの確認記録を残す。問題があれば公開を止める。

## 4. 性能・使いやすさ

暫定目標：合成400万画素の完全一致集計（走査開始〜整列・結果準備）がデスクトップで5秒以内、Worker走査・チャンク化した出力中のキャンセル操作への反応が250ms以内。復号・Canvas読出し中の応答は別途測定し、この値を全フェーズの保証とはしない。主要操作は画像差し替え・キャンセル・クリアを指し、解析設定は処理中に変更不可。復号時間・画素読出し時間・走査時間・ソート時間・出力時間を分けて記録する。実測機種・OS・ブラウザのバージョンは公開してよい一般的情報だけを残し、端末固有名は含めない。

D-04で暫定採用した20MiB・1600万画素・一辺8192pxの境界と、提案中の色数上限付近でメモリ・操作性を検証し、満たせない端末では上限を下げる。画素上限以内でも全ファイルの成功を保証しない。D-09でPC・スマートフォン両対応の方針は確定済み。上限の最終値、具体的な対応端末・ブラウザのバージョン、双方の性能目標は実測に基づいて正式な受入条件へ更新する。

初期版の必須条件として、PCのマウス・キーボードとスマートフォンのタッチ操作で、画像選択→条件設定→解析→画素確認→CSV/JSON保存→クリアの一連の操作、および解析中のキャンセルを検証する。スマートフォンはiOS Safari・Android Chromeを検証候補とし、レスポンシブ表示のエミュレーションに加えて実機確認を行う。両OSで保存先のファイル内容が正しいこと、画面回転で作業状態が失われないことも確認する。未確認のモバイル対応を完了扱いにしない。

保存は「準備→明示的なダウンロード」の2段階で試験し、長い準備時間でも保存できること、出力キャンセル後も表が使えること、Blobが条件変更・クリアで解放されることを確認する。OS側の完了をアプリが検知したと偽って表示しない。最大色数付近では、全rowsがUIへ複製されないこと、検索・ページ切替・JSON生成でメモリ使用量が急増しないことを計測する。

320px幅、デスクトップ、200%拡大、キーボード操作、タッチ、読み上げ、色コントラストを確認する。グラフが読めなくても表から同じ数値を取得できること。

## 5. 公開条件

P0/P1の未決定事項を解消し、P2の公開判断を完了する。必須の精度・状態管理・送信なし・保存なし検証を通過し、実測に合わせた上限、対応環境、精度の制約を画面とREADMEへ反映する。

プロジェクトサブパスでアセット・Worker・ダウンロードが動くこと、HTTPSで開くこと、公開成果物に許可以外のファイルがないことを確認する。READMEの「未実装・未公開」は実際に公開できた後に更新する。
