# 仕様レビュー結果

実施日：2026-10-19。対象：README、LICENSE、docs配下の要件・判断理由・外部仕様・内部仕様・セキュリティ・デザイン・リポジトリ・検証基準。アプリコードは未実装のため、動作・性能・安全性の合格判定は行っていない。

## 1. 結論

D-01〜D-10の基本方針に矛盾する新たな方針は必要なかった。ただし、処理段階ごとのキャンセル・失敗、全件データの持ち方、スマホでの保存、通信禁止の定義などに不整合や不足があった。以下を文書へ反映した。

画面試作と技術試作に進むための仕様は整理できた。全機能の本実装・公開に必要な実測や検証は未完了であり、現時点で「すべての仕様確定」「PC・スマホ動作保証済み」とはしない。

## 2. 発見事項と対応

「修正済み」は文書上の修正であり、実装完了を意味しない。追加の詳細は推奨設計として扱う。

| ID | 発見事項・影響 | 対応・理由 | 反映先 | 状態 |
|---|---|---|---|---|
| RV-01 | 通信0件という条件だと、解析時にWorkerの同梱ファイルを取得する構成と矛盾 | ユーザーデータ送信を禁止し、許可する静的取得を固定資産一覧に限定。目的である画像の非送信を検証できる条件にした | セキュリティ、検証、リポジトリ | 修正済み |
| RV-02 | 解析後にWorkerを終了する案と、Workerで全件出力する案が両立していない | 結果の集計・索引をWorkerに保持し、画面は概要とページだけ取得。画像の作業コピーは解析完了で解放 | 内部 | 修正済み |
| RV-03 | 全rowsを送ると、大量のJSオブジェクト複製でスマホのメモリを圧迫する | 論理的な出力モデルとUIのモデルを分離。コンパクトな配列・索引と全行イテレーターで扱う案 | 内部、検証 | 修正済み・メモリ実測待ち |
| RV-04 | 一律のエラー後全解放は「キャンセル後に画像を残す」と矛盾 | 入力失敗・解析失敗・出力失敗で解放範囲を分け、外部仕様と一致させた | 外部、内部、検証 | 修正済み |
| RV-05 | jobIdが解析開始後だけでは、古い復号結果が後から復活する | ファイル選択時のsourceId、解析jobId、問合せrequestIdで全段階の古い応答を無効化 | 内部、検証 | 修正済み |
| RV-06 | 長時間の出力準備後に自動保存するだけではスマホの保存操作を検証しにくい | 準備と最終ダウンロードを分け、最後は明示クリック。即時URL破棄も避ける | 外部、内部、検証 | 修正済み・実機試験待ち |
| RV-07 | 離脱イベントに依存すると即時消去を保証できず、非表示時クリアでは写真選択を壊し得る | タブ切替等は保持、検知できた離脱と履歴復帰は初期化。永続保存なしと物理消去保証を区別 | セキュリティ、内部、検証 | 修正済み |

| RV-10 | 初期モード、処理中の設定変更、選択取消、検索の挙動が不足 | 完全一致を初期値とし、処理中は設定を固定。画像差し替えは既定値に戻す。検索は表だけへ適用 | 外部、検証 | 補足済み |

## 3. 残る設計値と判断方法

ユーザーに内部アルゴリズムの細部を一つずつ選んでもらうのではなく、次の推奨案で試作し、結果と理由を記録する。承認済み要件を変更する必要がある場合は、その利用上の影響を説明して確認する。

| 項目 | 推奨する出発点 | 理由 | 最終化する時点 |
|---|---|---|---|
| 画像上限 | 合意した20MiB・1600万画素・一辺8192px | ファイル容量と展開後負荷を別々に制限する | PC・iOS・Androidでの実測後 |
| 完全一致の異なる色数上限 | 暫定100万色。超過は未完了エラー | 全画素を正確に集計する方針を保ち、無制限のメモリ増加を防ぐ。一般的な写真も超え得る | メモリ試作後。利用範囲を大きく狭めるなら分かりやすく説明して確認 |
| 類似色の区間幅 | RGBそれぞれ32、必要なら16へ切替 | 分類数と処理量を予測しやすくする | サンプル結果・画面試作で確認 |
| 代表色 | 所属画素のRGB平均を四捨五入 | 実際の構成を要約し、区間の固定中央色より入力を反映できる | 集計テストと表示説明で確認 |
| ページ・グラフ | 50行、上位10グループ＋その他 | スマホでの描画負荷を抑え、全件は保存・ページ移動で確認可能にする | 画面試作 |
| 出力 | 固定スキーマv1、CSVはBOM付きUTF-8、JSONは条件付き全件 | 検証可能性と表計算ソフトでの扱いやすさ | 出力・実機試験 |
| ヘッダー走査 | 最大64KiB単位、構造要素は暫定10万件 | ファイル全体の一括複製・不正な長さ・過度な走査を避ける | パーサー試作 |
| ブラウザ | デスクトップ主要4種とiOS Safari・Android Chromeを候補 | PC・スマホ双方の要件を検証する | 公開前に実際のバージョン・機種を明記 |
| 性能 | PC400万画素5秒、Worker中キャンセル250msを暫定目標 | 具体的に測れる出発点とし、未測定性能を約束しない | 両モバイルを含む性能試作後 |
| 公開運用 | GitHubの非公開脆弱性報告機能の利用可否を公開準備で確認 | 個人メールを公開せず報告経路を設ける | SECURITY.md作成・公開前 |

「不透明のみ」の追加、クリップボードコピー、ピンチ操作、複数画像、知覚クラスタリングは初期版の必須条件にしない。候補が文書にあるだけで実装必須と解釈しない。

## 4. 次の工程と完了条件

1. 画面試作：合成画像・仮データでPC／スマホの選択・設定・プレビュー・結果・保存準備を確認する。空状態・解析中・失敗・対象0も含める。実画像をリポジトリへ追加しない。
2. 技術試作：PNG/JPEG/WebPの復号・向き・全数集計、Workerの結果保持、全件出力とキャンセルを検証する。既知RGBA配列の数値検査と、ブラウザ経由の特性検査を分ける。
3. 実測結果の記録：端末識別情報を除いた機種・OS・ブラウザ版、入力寸法・色数、処理段階ごとの時間、メモリの観測範囲、成功・失敗を表に残す。測定できないメモリ量を推測で埋めない。
4. 詳細設計の最終化：上記の値と対応環境を仕様へ反映し、必要な利用上の変更だけをユーザーへ確認する。合格後に本実装・受入試験へ進む。

画面と技術は小さな試作として並行して検討できるが、本レビューではコード作成・依存導入・デプロイは行わない。プライバシー検証・実機保存・上限試験が未実施のまま公開しない。
