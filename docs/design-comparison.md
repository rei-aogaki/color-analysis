# デザイン比較の試作

状態：2026-10-19、ユーザーの指示によりA（ギャラリー型）を暫定採用し、全機能画面に統合済み。A・Bの比較用画面は参考として維持する。[統合後の画面仕様](design.md)

## 比較する2案

| 案 | 見せ方 | 狙い |
|---|---|---|
| A：ギャラリー型 | 無彩色の背景、大きな画像、右側の解析パネル | 操作と結果を見つけやすくし、画像と色を主役にする |
| B：編集・誌面型 | 明朝体の見出し、大きな数値、細い罫線と余白 | 写真集や雑誌のような、視覚的な印象を持たせる |

推奨したAをユーザーが暫定採用した。設計上の推奨理由は、繰り返し使う解析ツールとして、画像・色の割合・操作の関係が読み取りやすいため。ユーザー自身の採用理由は追加で推測しない。Bは比較参考として残す。細部は全機能を統合した画面で見直す。

## 次の工程

1. 実施済み：Aの画面構成に、既存の完全一致・似た色・透明度設定・画素検査・CSV/JSON保存を統合した。「色の傾向」を最初に見せ、詳細な設定と検査は必要なときに開ける構成とした。
2. 回帰テスト、PC・スマホ幅、キーボード操作は確認済み。スマホ実機もユーザーからOKの報告を受けた。端末・ブラウザのバージョン別確認は継続する。
3. 統合画面をユーザーが確認した後、公開用ファイル・Git履歴・プライバシー説明を点検し、GitHub Pagesの公開準備へ進む。

画像の周囲は無彩色とし、解析色に合わせて画面全体を着色しない。OS標準フォントを使い、外部フォント・画像サービスを読み込まない。

## 操作と比較条件

本番ビルドをプレビューし、表示されたURLの末尾に `design.html` を付けて開く。画面上部のA・Bボタンで切り替える。

- 切り替えによって画像、解析結果、強調中の色系統は変わらない。
- 初期画像はコードで描いた風景であり、実写写真ではない。表示する数値は実際の画素を集計した値。
- 自分の画像を選択できる。画像はブラウザ内で解析し、送信・永続保存しない。利用者の画像をリポジトリに含めない。
- 色系統のボタンで該当する位置を強調し、元画像に戻せる。強調は集計値や保存内容を変更しない。
- 元の画素全体を既存の色系統分類Workerで集計する。表示サイズに合わせて集計画像を縮小しない。

比較ページは「色の傾向」とJSON保存に絞った試作。完全一致、座標検査、CSVなどは全機能画面で利用する。

## 構成と検証

`design.html` と `src/design/` に比較用の構成をまとめ、解析・画像検証は既存の実装を共用する。Viteの複数ページビルドに含める。

`npm run test:design` で6群の検証が成功した。Chromium 148で、同一結果の保持、強調の切り替え、JSON、画像入力と不正形式の拒否、外部通信・ブラウザ保存の不使用を確認した。1440・390・320px幅で横はみ出しがないこと、画像全体の表示と縦横比、モバイルの縦配置を確認し、タッチ操作のエミュレーションも実施した。

スクリーンショットはGit除外済みの `.local/` に保存する。スマートフォン実機とSafariでの確認、アクセシビリティ全体の監査は今後の工程。Aへの全機能統合の結果は[統合記録](design-integration.md)を参照する。
