# 色もどしブラシ

状態：2026-10-20、第1段階を実装（ブランチで検証中、未公開）。§9の判断事項はユーザーが承認済み。名称は仮称「色もどし」。実装結果と設計からの変更点は§10、スマホ表示の不具合修正は§8を参照する。[要件](requirements.md)・[判断理由](decisions.md)へのD-11としての記録は、公開時に行う。

## 1. 目的と体験

モノクロにした写真を、指やマウスでなぞった部分だけ元の色に戻す加工機能。Accent（Selective Color）のように色で自動的に残すのではなく、使う人が自分の手で「どこに色を戻すか」を決める。丸ブラシに加え、くま・わんちゃんの形で色を戻すスタンプ／ブラシを用意する。

体験として大事にすること：

1. **触った瞬間に色が戻る**：遅延やカクつきがなく、指の下に形が現れる。
2. **失敗しても怖くない**：ひと筆ずつ元に戻せる・やり直せる。はみ出しはモノクロに塗り戻せる。
3. **スマホが主役**：片手の親指で届く位置に操作を置き、ページのスクロールや画面サイズの変化に邪魔されない。
4. **保存までが短い**：iPhoneでは「写真に保存」まで2タップで終わる。

## 2. 現在のコードから分かったこと（見積もりの裏取り）

| 前回の想定 | コード上の事実 | 設計への影響 |
|---|---|---|
| 画像読み込み・Canvas表示・拡大・座標取得が使える | `load()`が原寸`ImageData`（`pixels`）を保持し、`#preview`を原寸Canvasとして描画。`resizePreview()`で表示サイズを決め、座標は`getBoundingClientRect`の比率で計算（`src/main.ts:101-133, 358`） | 画素データ・座標変換はそのまま流用できる |
| 今のドラッグ操作は画像移動に使われている | マウスのドラッグは枠のスクロール、タッチは`touch-action: pan-x pan-y`でブラウザに任せ、タップで画素検査（`src/main.ts:347-361`、`src/styles.css:69`） | 編集中は別の操作体系が必要。後述の編集画面で分離する |
| 色系統の強調表示が土台になる | `showFamily()`は全画素を走査して別の`ImageData`を作り、`inspect()`が毎回Canvas全体へ`putImageData`して選択マーカーを描く（`src/main.ts:144-151, 215-253`） | 仕組みは参考になるが、なぞるたびに全体を描き直すと重い。変化した範囲だけを描き直す専用処理が必要 |
| 1,600万画素で約64MB | 上限は1,600万画素（`src/image/read.ts:1`）。読み込み後は`pixels`（64MB）とCanvas（64MB相当）が常駐し、解析中はWorkerへ複製（64MB＋ラベル16MB） | Canvasや`ImageData`を何枚も増やさない。マスクは1画素1バイトの配列にする |
| 色の集計・CSV/JSON出力はそのまま | 解析はWorker内で完結し、画像表示とは独立 | 変更不要。編集は解析結果も数値も変えない |
| 新規の編集用モジュール | 既存は`src/main.ts`へ機能を集約。純粋な処理は`src/analysis/`などに分け、`node --test`で単体テストしている | 画素計算は画面に依存しないモジュールに分け、単体テストできるようにする |

結論：前回の「中くらいの改修」という見立ては妥当。ただし「最高の使い心地」を前提にすると、スマホ専用の編集画面とUndoが必須になり、工数は前回の上限寄りから少し超える（§7）。

制約として、CSP（`default-src 'none'`ほか）、外部ライブラリなし、永続保存なし、元ファイル名を出力しない方針（[セキュリティ・プライバシー](security-privacy.md)）を守る。ブラシ形状はコード内のパス定義で描くため、外部画像は不要。

## 3. 画面と操作（UI/UX）

### 3.1 入り口

画像を読み込むと、プレビュー見出しの横に「色もどしで遊ぶ」ボタンを表示する。解析しなくても使える。解析後に「どこが、その色？」で系統を選んでいる場合は、2段階目で「この系統の色を残した状態から始める」を選べるようにする（§6）。

### 3.2 編集画面（推奨：全画面）

編集は通常画面の中ではなく、画面全体を使う専用の編集画面で行う。

理由：通常画面の中でなぞる操作を受け付けると、ページのスクロールと指の動きが衝突する。また、スマホのアドレスバーの伸び縮みで画像の大きさが変わる（§8と同じ原因）と、塗っている最中に位置がずれる。全画面にすると、画像を最大の大きさで表示でき、操作も親指の届く下部へまとめられる。

```
┌──────────────────────────┐
│ ×閉じる        ↶  ↷        保存 │  上部：閉じる・元に戻す・やり直す・保存
│                                │
│                                │
│        （画像：全体表示）        │  画像：残りの領域いっぱいに縦横比を保って表示
│                                │
│                                │
├──────────────────────────┤
│ [色を戻す|モノクロに戻す]  ◐比較 │  モード切替と、押している間だけ元画像を表示
│ ●丸  🐻くま  🐶わん     ○──●── │  形の選択と、大きさスライダー
└──────────────────────────┘
```

- PC（幅900px以上）でも同じ構成で、操作は右側の縦帯に置く。
- 編集画面は`position: fixed`で表示し、背面のページはスクロールさせない。高さは`100dvh`を使い、iPhoneの下部ホームバーには`env(safe-area-inset-bottom)`の余白を取る。
- 「閉じる」で通常画面へ戻る。塗った内容は、同じ画像を開いている間は保持し、再度開くと続きから編集できる。クリア・画像の差し替え・ページ離脱では破棄する（既存の方針と同じ）。

### 3.3 塗る操作

| 操作 | 結果 |
|---|---|
| 1本指でタップ／クリック | その位置に、選んだ形を1つスタンプする |
| 1本指でなぞる／ドラッグ | 通った道に沿って形を並べる。丸は線として連続し、くま・わんは間隔をあけて並ぶ |
| 2本指 | 画像の移動・拡大縮小（第2段階）。第1段階では「移動」ボタンで移動モードに切り替える |
| 「色を戻す」／「モノクロに戻す」 | 前者は色を戻し、後者ははみ出した部分をモノクロへ戻す。くま形の消しゴムも使える |
| 「比較」を押している間 | 加工前のカラー画像を表示し、離すと戻る |
| ↶／↷ | ひと筆（指を置いて離すまで）単位で、元に戻す／やり直す |
| 全部モノクロに戻す | 確認の上でマスクを空にする。この操作もUndoできる |

- タッチ中は、指で隠れて見えない位置を補うため、ブラシの外形を少し大きく表示する。マウス操作では、カーソル位置に常に外形を表示する。
- 大きさは「画面上での見た目の大きさ」で決め、スライダーの横に実寸の目安を表示する。画像の解像度によって同じ設定でも小さすぎる、といったことが起きないようにする。
- 速くなぞっても途切れないよう、`getCoalescedEvents()`で間引かれた座標も使い、前回の位置から今回の位置までを一定間隔で補間する。
- 描画は`requestAnimationFrame`ごとにまとめ、変化した範囲だけを描き直す。

### 3.4 ブラシの形

| 形 | 第1段階 | 既定の並び間隔 | 形の設計方針 |
|---|---|---|---|
| 丸 | ◯ | 大きさの15%（線になる） | ふち0〜1画素程度を自然になめらかにする |
| くま | ◯ | 大きさの110%（1つずつ離れる） | 丸い顔に丸耳2つ。小さくても耳でくまと分かる形 |
| わんちゃん | ◯ | 大きさの110% | 垂れ耳と鼻先で犬と分かる横顔または正面顔。24px程度でも判別できるか検証する |
| 肉球・ハート・星・お花 | 第2段階 | 110% | 同じ仕組みで追加できる |

形は100×100の座標系で定義した`Path2D`のパスとして`src/editor/shapes.ts`に置く。くま・わんちゃんは並べたときに同じ向きで規則正しく並ぶ。第2段階で「向きをランダムにする」「間隔」を追加する。

### 3.5 保存

- 「保存」でPNGを作る。iPhone・Androidでファイル共有に対応するブラウザでは共有シートを開き、「画像を保存」で写真アプリへ保存できるようにする。非対応の環境では従来どおりダウンロードする。
- ファイル名は元ファイル名を使わず、`color-analysis-brush.png`のような固定名にする。Canvasから作るPNGには撮影日時・位置情報などのメタデータは入らない。
- 原寸で書き出すため、1,600万画素ではPNGが数十MBになり、作成に数秒かかる場合がある。作成中は進捗表示を出し、二重押しを防ぐ。

### 3.6 アクセシビリティ

ボタンは44px以上。形・モードはラジオボタン相当の`aria-pressed`で状態を伝える。なぞる操作そのものは代替が難しいため、「全部モノクロに戻す」「この系統の色を残して始める」など、なぞらなくても結果を作れる操作を用意する。編集画面を開いたらフォーカスを編集画面内に閉じ込め、Escで閉じる。

## 4. 内部設計

### 4.1 データ

| データ | 形式・大きさ（1,600万画素時） | 役割 |
|---|---|---|
| 元画像 | 既存の`pixels`（64MB）を共有 | 色を戻すときの元の色 |
| モノクロの明るさ | `Uint8Array`（16MB）。編集を開くときに作成 | モノクロ表示用。毎回計算し直さない |
| マスク | `Uint8Array`（16MB）。0＝モノクロ、255＝元の色 | どこに色が戻っているか。中間値はふちのなめらかさ |
| Undo履歴 | 1筆ごとに、変化した範囲のマスクの変化前後だけを保存。合計32MBまでで古いものから破棄 | 元に戻す／やり直す |

表示は既存の`#preview`とは別の、編集画面用Canvasを1枚使う。Canvasや画像全体の複製は増やさない。追加メモリは最大で約64MB（明るさ・マスク・履歴の合計）。

### 4.2 描画の流れ

1. ポインター位置を画像の座標へ変換する。
2. 形を、その大きさの小さな作業用Canvasへ描き、形の範囲を得る（同じ形・大きさなら再利用する）。
3. マスクの該当範囲へ、「色を戻す」なら大きい方の値、「モノクロに戻す」なら小さい方の値で書き込む。
4. 変化した範囲について、`モノクロ＋（元の色－モノクロ）×マスク÷255`を計算し、その範囲だけ`putImageData`する。

モノクロの明るさは、sRGBの値を線形の明るさへ変換して計算し、写真の明暗の印象が変わりにくいようにする。透明な部分は透明のまま保つ。

### 4.3 モジュール構成

| ファイル | 役割 | テスト |
|---|---|---|
| `src/editor/mask.ts`（新規） | 明るさの作成、マスクへの書き込み、合成、範囲計算、補間。DOMに依存しない | `tests/unit/mask.test.ts`で数値を検証 |
| `src/editor/history.ts`（新規） | 1筆単位の差分、Undo/Redo、上限管理 | `tests/unit/history.test.ts` |
| `src/editor/shapes.ts`（新規） | 丸・くま・わんちゃんの形と既定の間隔 | ブラウザ検証で描画を確認 |
| `src/editor/editor.ts`（新規） | 編集画面の開閉、ポインター操作、描画予約、保存 | ブラウザ検証 |
| `src/main.ts` | 入り口ボタン、画像・クリア・差し替え時の連携。`clear()`で編集状態も解放 | 既存検証に追加 |
| `index.html` / `src/styles.css` | 編集画面の構造と、スマホ・PCのレイアウト | 画面幅別のスクリーンショット |

## 5. 既存機能との関係

- 解析結果・割合・CSV/JSONは変更しない。編集は表示と保存用の画像だけに作用する。
- 画素検査のタップと選択マーカーは、編集画面では使わない。保存画像にマーカーは入らない。
- 解析中でも編集画面を開ける。画像の差し替え・クリアでは、解析と同様に編集状態も破棄する。

## 8. 既存の不具合：スクロールでプレビューの大きさが変わる

**現象**：スマホで縦長（9:16）の画像を読み込み、ページをスクロールすると、プレビュー枠と画像が少し小さくなったり大きくなったりする（2026-10-20のユーザーの画面録画で確認）。

**原因**：`resizePreview()`が枠の高さの上限を`window.innerHeight * 0.72`から計算し、`window`の`resize`イベントで再計算している（`src/main.ts:121, 338`）。iPhoneのSafariではスクロールに合わせてアドレスバーが伸び縮みし、そのたびに`innerHeight`が変わって`resize`が発生する。縦長の画像は高さの上限で大きさが決まるため、横長の画像より影響が目立つ。

**対応（2026-10-20、修正済み・iPhone実機での再確認待ち）**：

1. 高さの基準を、アドレスバーの状態で変わらない「小さい方の画面の高さ」（CSSの`100svh`）に変えた。`height: 100svh`の目に見えない測定用の要素を置き、その高さを読む（`src/main.ts`の`stableViewportHeight`）。`svh`に対応しないブラウザでは`100vh`を使う。iPhoneのSafariでは`100vh`もアドレスバーの状態で変わらない。
2. 画面の回転やウィンドウの大きさの変更では、これまでどおり再計算する。
3. [画面仕様](design.md)へ、基準にする画面高を明記した。
4. ブラウザ検証に、`innerHeight`だけを変えて`resize`を発生させても枠の大きさが変わらないことを確認する項目を追加した。修正前のコードではこの検証が失敗し（枠が344×648pxから200×360pxへ縮小）、修正後は成功することを確認した。Chromiumはアドレスバーの伸び縮みを再現できないため、公開後にiPhone実機で確認する。

## 10. 第1段階の実装結果（2026-10-20）

**実装した範囲**：§6の第1段階すべて。モジュール構成は§4.3のとおり（`src/editor/`）。

**設計から変えた点**

| 項目 | 変更内容 | 理由 |
|---|---|---|
| 全部モノクロに戻す | 確認ダイアログを出さず、すぐ実行する。↶で元に戻せることを表示する | Undoで戻せるため、確認の手間を省く |
| 拡大と移動 | 表示倍率（全体・2倍・4倍）と「移動」ボタンで対応。2本指の操作は第2段階 | §3.3の第1段階の範囲どおり |
| 塗り始め | 画像の外側の余白からなぞり始めても塗れるようにした | 端まで塗りやすくするため（プレビュー確認で発見） |
| 保存 | 「保存」でPNGを作成し、「共有・写真に保存」または「ダウンロード」を選ぶ2段階 | 作成に時間がかかると、共有シートを開く許可（直前の操作）が切れるため。CSV/JSONの保存と同じ流れ |
| ブラシの大きさ | 画面上6〜200pxを指数的に調整し、画像上の大きさを併記する | 小さい筆の細かい調整と、大きい筆の両方に対応するため |

**検証**

- 単体テスト（`tests/unit/brush.test.ts`）：モノクロの明るさ、合成、スタンプ、はみ出し、補間、Undo/Redo、履歴のメモリ上限。
- ブラウザ検証（`tests/browser/check.mjs`）：タップ・ドラッグでの色の復元、モノクロに戻す、くまの目の穴、元に戻す／やり直す／全部モノクロ、元画像の比較、原寸PNGの保存内容、閉じて再度開く、クリアでの破棄、解析結果が変わらないこと、スマホ幅のレイアウトとタッチ操作。
- 1,600万画素（デスクトップのChromium 148、ヘッドレス）：開く0.26秒、塗る間の描画1コマ約17ms、元に戻す0.13秒、PNGの作成約7秒。スマホではさらに時間がかかる見込みのため、作成中は状態を表示し、二重押しを防ぐ。
- 未確認：iPhone・Android実機での操作感と速度、共有シートからの「画像を保存」。公開前にユーザーの実機で確認する。


## 11. 見せ方の改良（A案、2026-10-20）

**きっかけ**：ユーザーが自分の写真で試したところ、くま・わんちゃんの形がほとんど分からず、遊んでいて面白くなかった。原因は、スタンプの中が「その場所の元の色」に戻るだけで、淡い色（白い壁・白い服・肌）の上では戻した色とモノクロの差が小さく、形の輪郭が見えないため。並べた形がつながって帯に見えること、目と鼻の穴が小さいことも重なっていた。

ユーザーは、仕組みを変えるB案（タップした範囲を似た色ごとまとめて戻す）より先に、今の仕組みのまま形を見えやすくするA案を選んだ。

**追加した内容**（「見せ方の調整」。幅900px以上では開いた状態、スマホでは折りたたむ）

| 項目 | 内容 | 初期値 |
|---|---|---|
| ステッカー風のふちと影 | 形のまわりに白いふち（大きさの約7%）と、下側にうっすら影を付ける。目と鼻の穴はふちにも開け、背景の写真が見える | オン（これから置く形に付く） |
| 色の鮮やかさ | 戻した色を、明るさを保ったまま最大1.8倍まで鮮やかにする | 40（1.32倍） |
| 背景の暗さ | モノクロ部分を最大60%暗くする | 30（18%） |
| 重ならない配置 | くま・わんちゃんでなぞると、前の形やふちと重ならない位置にだけ置く。タップでは重ねて置ける | 常に有効 |

**内部**：ふちと影は、色のマスクとは別の1画素1バイトの配列で持つ（1,600万画素で各16MB）。元に戻す／やり直すは3つの配列をまとめて扱う。合成の順序は、モノクロ（暗さ）→影→白いふち→戻した色（鮮やかさ）。「モノクロに戻す」はふちと影も消す。鮮やかさと暗さは画像全体の見せ方で、履歴の対象外。

**検証**：単体テストに合成の順序・鮮やかさの上限・重なり判定・複数配列の履歴を追加。ブラウザ検証に、ふちが白くなること、背景が暗くなること、色が鮮やかになること、元に戻すでふちも消えることを追加した。
