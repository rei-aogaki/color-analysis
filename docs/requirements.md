# 要件・決定管理

## 1. 現状

開始時点の追跡対象は、プロジェクト名だけを記載したREADMEのみで、画面・プログラム・テスト・デプロイ設定・ライセンスはなかった。仕様策定後、合意したMITのLICENSE、TypeScript＋Viteのローカル試作、単体・ブラウザ検証を追加した。現在はPC／スマホ画面と解析処理を試せる段階で、実機検証・最終上限・公開設定は未完了。[試作の検証結果](prototype-results.md)を参照。

## 2. 目的

画像に含まれる色を全画素の集計で調べ、件数・割合を検証可能な形で示す。ピクセル単位の検査を優先し、配色を把握するための類似色集計も提供する。見た目の色と、集計に使った数値を混同させない。

## 4. 精度の境界（D-01確定）

「厳密」には二つの意味がある。

1. ブラウザが復号し、Canvasから読み取ったsRGB・8bit RGBAの全画素を、縮小や間引きなしで正しく数える。
2. ファイルの元のサンプル値・ビット深度・色空間を、そのまま維持して検査する。

初期版は1（A案）を採用することにユーザーが合意した。sRGB・8bit RGBAという取得形式などの実装詳細は引き続き提案とする。2には専用デコーダー、ICCプロファイル・高ビット深度・透明度の取り扱いを含む追加設計が必要。Canvasでは色空間の変換や透明度に伴う値の変化があるため、2を保証できない。[HTML Standard](https://html.spec.whatwg.org/multipage/canvas.html#pixel-manipulation)

完全一致集計では読み取った全画素を処理する。検査のために画像を自動縮小しない。類似色集計でも全対象画素を集計し、結果にアルゴリズムと設定を付ける。見やすさのためのプレビュー縮小は解析とは独立させる。

## 5. 初期版の範囲（提案）

対象：画像1枚、静止PNG/JPEG/WebP、全体集計、透明度条件、色テーブル、全件数、単一画素の座標とRGBA確認、結果のCSV/JSON出力、キャンセル、クリア。

対象外の提案：サーバー、会員機能、履歴、共有URL、外部URL画像の取得、広告、AI API、カメラ、複数画像比較、範囲選択集計、画像編集、印刷用CMYK検査、HDR、元ファイル値の保証、PWA・Service Worker。上記のうち確定事項と重なる内容は各R項目に従う。

入力形式の範囲はD-03で確定済み。SVG/GIF/HEIC/AVIF/TIFFなどPNG・JPEG・WebP以外、およびAPNG・アニメWebPを含むアニメーションは初期版では対象外とする。

## 6. 技術的コストの見通し

以下は相対的な開発負担の見積もりで、工数や金額の確約ではない。

| 項目 | 相対負担 | 主な理由 |
|---|---|---|
| 全画素の完全一致集計 | 小〜中 | 計算自体は単純。大量の異なる色とメモリ管理に工夫が必要 |
| 単一画素検査 | 中 | 拡大表示、座標変換、タッチ・キーボード対応が必要 |
| 固定の減色による類似色集計 | 中 | 再現性を得やすい。境界で近い色が分かれる特徴がある |
| 知覚的なクラスタリング | 中〜大 | 距離関数、収束、再現性、性能の検証が増える |
| 元ファイルの色値を保証 | 大 | 形式別デコーダー、色管理、透明度、高ビット深度への対応が必要 |
| 全端末・全ブラウザで同一結果を保証 | 非常に大 | ブラウザの復号・色管理・保護設定に差がある |

サーバー代や画像解析API代の不要な構成を取れる。GitHub Freeの公開リポジトリでPagesを利用できるが、帯域などの利用制限・規約はある。「誰でもどこでも」は対応ブラウザと通信環境を満たす範囲であり、全地域の接続や無停止を保証しない。[Pages概要](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)、[利用制限](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)
